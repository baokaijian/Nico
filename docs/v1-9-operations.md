2026-10-25：家长明确选择“尚未决定，先交付配置与演练”。本期正式上传、调度和外部通知均未启用，不能视为已有离站容灾。

## 差距、涉及文件和风险

V1.6已有认证加密、校验、恢复演练、容量统计和发布指纹检查，但没有配置驱动的端到端作业，也没有目的地回读或有限重试通知。本期新增 `scripts/reliability-runner.mjs`、`shared/operations-alerts.mjs`、`scripts/notify-operations.mjs`、配置示例及协议测试；复用 backup-job/backup-crypto，不改实体、迁移或 Edge 依赖。HealthPanel说明实际启用状态，两个发布工作流增加固定技术字段的失败摘要和可选通知。

运行器只接受手工准备的不可变完整导出目录，至少含平台 `nico-backup-v1` 的 snapshot.json 和所有当前、回收站及历史媒体引用对应的 uploads 文件。年度选择性归档不是整库备份。未知、远程或缺失媒体引用会阻断，不能冒称完整。输入前后摘要必须相同；此检查不能替代首次正式导出的在线 revision/存储清单前后核对。

本运行器要求当前所有业务集合及profile/publishing/trash明确存在，不能将缺字段默认补空。旧版备份仍可用原backup-job verify和原恢复流程读取，不把旧格式误标为当前完整离站备份。冻结报告baseline中的素材、纪念册mediaSnapshots及它们的回收站/历史版本同样纳入文件预检。通过安全配置后即创建私人作业目录，完整性/容量预检失败也保留脱敏回执与重试事件；配置本身不可信时只输出封闭失败结果，不向未核实路径写文件。

初期仅支持明确的私有挂载目录，不内置未知云服务上传。输入、工作、目标、密钥相互隔离，输出在仓库之外，拒绝符号链接、特殊文件及公开目录；目录0700、文件0600。单文件100MiB、500文件和总量256MiB硬上限，超出须先设计分包，不悄悄跳过素材。内存加密有额外开销，不宜在小内存设备执行大包。

步骤：配置预检→完整性预检→加密→本机解密校验→输入稳定性核对→唯一密文包投递→回读摘要/解密校验→无内容回执。每次独立运行ID，失败不删除旧包，不自动清理真实资料；投递后校验失败的包标记失败，不作为可恢复备份。只有加密包进入目标目录，源清单在密文中；包内条目文件名可见，故目标仍必须私有。

通知仅有封闭事件/错误类别、内部运行ID和数值；不转发异常正文、路径、姓名、原片URL或令牌。HTTPS主机必须显式允许，禁止重定向，最多3次。缺少通知配置明确“未配置”；失败保留私有待发送事件，手工重试沿用运行ID。通知故障不能让备份失败变成功。GitHub失败摘要是确定状态，外部送达另看回执。

## 配置、启用与恢复

将配置示例复制到仓库外私人目录，保留 enabled=false，待家长选定具体目的地、持有人和权限后再更改。公钥用于加密；恢复私钥由家长放在独立密码保险库/离线加密介质，不能放备份目标、输入目录、代码或CI日志。验证时临时只读挂载私钥，验证后卸载；本期没有代家长创建正式密钥或选择服务。

执行 `npm run operations:run -- --config /绝对私人目录/operations.json`；无配置或disabled立即停止，不读取档案。`npm run operations:run -- --rehearse` 只使用隔离协议资料、临时SQLite与临时密钥；回执按阶段区分实际演练与生产恢复。

正式启用后建议每日一次、每周独立恢复演练，频率和保留期由家长按容量与费用决定；本期没有安装计划任务。现有单时点9对象/94,317,512字节，密文Base64约增加三分之一，再加快照/清单/认证开销；存储预算约为实际单包字节×保留份数，并计入取回流量。供应商、单价未定，不能编造费用或SLA。storage-report继续只读统计，尚无增长周期基线，不设凭空容量增长/延迟阈值。

恢复：从授权私有目标取回密文及回执→独立设备临时挂载私钥→backup-job verify核对摘要、数量和新鲜度→解密到私有临时目录→隔离库检查所有源ID、历史、回收站和媒体字节→家长审核后另行决定生产恢复。禁止用旧包覆盖更新的正式事实。现有协议SQLite演练不代表实际生产恢复成功。

可选通知配置使用环境变量 NICO_OPERATIONS_WEBHOOK、NICO_OPERATIONS_ALLOWED_HOSTS，绝不写前端变量；当前均未配置。修改通知目的地仍须先确认其接收的数据范围。失败、版本不符、完整性失败可立即触发固定事件；统计类阈值等待实际观测。

失败通知未送达时，在私有作业目录保留pending-alert.json。目的地配置完并核对接收范围后可执行 `node scripts/notify-operations.mjs --pending-file /绝对私人作业目录/pending-alert.json`，沿用事件ID；只在返回delivered后人工标记处置，工具不自动删除事件。接收端可按Idempotency-Key去重。没有可信工作目录的配置失败只会有命令行回执，应由运行调度者保存并排查。
