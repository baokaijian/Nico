# 数据模型与兼容策略

现状：本机/云端共同使用版本化 JSON 业务状态，SQLite/Postgres 台账、备份和逻辑删除字段提供保存保护。先增量增强业务实体及服务端约束，避免同时更换存储和业务界面。跨运行时 MJS 保留兼容；增量引入 TypeScript 契约与检查。

| 目标实体 | 现有位置/计划 | 关系 |
|---|---|---|
| Athlete | profile，当前单一 Nico 归属 | 全部记录 athleteId |
| TrainingSession | trainings | 计划课次、训练组、媒体 |
| TrainingSet | trainings[].sets，组ID在单次训练内唯一 | 泳姿、每次距离、计划次数、实际次数 |
| TrainingTemplate | trainingTemplates，私有版本化安排 | 被训练按ID/版本引用，训练另存所用组表 |
| TrainingPlan | plans / planHistory | 来源记录、版本、课次 |
| SwimPerformance | swim | 项目、timeMs、有效性、赛事/训练、媒体 |
| SkillDefinition / SkillAssessment | 后续新增集合 | 可配置标准、评估人/日期/依据、历史 |
| GrowthGoal | goals 增强 | 标准、基线、目标、计划和确认完成证据 |
| MediaAsset | media | recordId、标签、授权公开、原片/副本 |
| Competition / Milestone | 后续新增集合 | 成绩、技能、训练或独立人工记录 |
| CoachFeedback | 现有 coachNotes / annotations，后续结构化 | 来源、训练/媒体、作者与日期 |
| AuditLog | 计划新增服务端审计 | 操作、主体、时间、请求标识、前后版本 |

服务端关系验证是当前 JSON 模型的外键约束。增加关系必须校验目标存在、归属一致、被逻辑删除时的恢复语义。新记录使用唯一 ID、createdAt/updatedAt/athleteId；历史未知创建时间不可伪造为业务发生时间。

时间迁移：字符串原值保留；以精确解析得到整数 timeMs，旧 seconds 为兼容派生值，mm:ss:cc 为显示值。不同精度不能经显示字符串回写而丢失毫秒。无效或冲突值列入只读审计，不能猜测修复。既有有效录入不擅自改为失格；缺少有效性时保留兼容解释并提供人工确认。

### 成绩模型 v1（V1.0 第二阶段）

`shared/performance.ts` 是前端、本机及云端共用的 TypeScript 实现。`performanceSchemaVersion: 1` 独立于原 `schemaVersion: 2`，不删除旧字段。

- `timeMs` 为权威整数毫秒；`previousTimeMs`、`winnerTimeMs` 可为空，不伪造历史成绩。`timeInput` 及对应可选输入保留当前成绩的精确输入，修改前版本由备份保存。
- `time` 按家长选择显示 `mm:ss:cc`，达到小时后为 `hh:mm:ss:cc`；`seconds` 仅为旧显示值的兼容副本。PB、差值、趋势、改善率使用权威毫秒，禁止重新解析舍入后的 time 作为计算依据。
- 接受正数秒（最多三位小数）、旧分:秒小数、分:秒:百分秒及小时形式；范围沿用至少 0.010 秒，最多 24 小时。显示可舍入百分秒，编辑会载入完整精度；例如 56.171 秒显示 00:56:17，仍按 56171 毫秒计算。
- `validityStatus` 为未核验/有效/失格/无效，另有可选 `validityNote`。缺少既有确认时迁移为未核验，不能自动认定有效。只有有效且已知25m/50m池长的同距离、泳姿、池长成绩参加 PB；未知池长不合并。历史列表保留全部记录及计时方法标签。
- 有效样本不足两条不计算改善率或绘制趋势；极小的正改善显示“小于0.01%”，并保留实际毫秒差。走势图最小纵轴跨度为1秒，避免放大微小差异。

`npm run audit:performance` 默认只读并将前后副本存入忽略的 review；`-- --apply-local` 才写本机当前事实库，必须通过 CAS 和写前备份。`-- --input review/最新云端快照.json --cloud-sql` 只生成私有 SQL，不会把本机副本覆盖云端。云端迁移与向前回滚均校验完整快照、版本及逻辑删除台账，并锁定相关行；发生后续写入或删除标记变化则拒绝整库覆盖，改用向前修复。所有旧备份、原始输入及原视频保持原件不变；旧备份恢复会自动补齐当前毫秒版本，并保留较新记录于回收站及计划历史。

迁移先在副本验证，生成迁移前备份与差异报告；CAS 成功才写入，重复执行不重复修改。回滚使用备份并保留迁移后新增记录/历史，不直接覆盖整个现有状态。关系型拆表和删除任何旧字段属于高风险变更，另给迁移、双读及回滚方案后执行。

计划恢复必须合并当前与备份历史；同 ID/版本不同内容不可静默覆盖；后续版本高于所有历史。媒体恢复不物理删除对象。业务逻辑删除继续保留 deletedAt/deletedBy；公开摘要剔除已撤回或删除项。

## 已有打卡集合的台账兼容补丁

### 实际训练模型（第三阶段）

`shared/training.ts` 统一前端、两个后端及统计。`entryMode` 为快速/训练组，`completionStatus` 为未记录/已完成/部分完成/未完成/已取消；另有泳姿、实际分钟/距离、感受、备注、教练原话。旧记录原文保留，不自动补造训练、状态或创建时间。

训练组包含 ID、任务、泳姿、每次距离、计划次数、实际次数、间歇、打腿标记。最多50组，次数为0–2000整数，每次距离0.01–5000米且最多两位小数，单次实际/参考总量不超过50000米。按整数厘米累加后换算为米。任一实际次数未知则完整总量为空，另展示已知部分；0保持为明确零。快速模式保留人工实际总量。未完成/已取消不能填写正的实际量；已完成组表不能仍缺次数或低于已填计划次数。

模板仅存参考安排、版本和说明，拒绝实际次数。使用模板及复制训练均重置实际量、感受、日期、影像、ID和请求标识；新训练日期默认今天。训练保留所用模板版本及独立组表。`mediaIds` 可关联多素材，不覆盖素材原来的 `recordId`；删除素材后保留既有关联痕迹。计划课次新关联由服务端校验并捕获原计划版本及课次快照，后续编辑不改写；旧记录未记版本则保持未知。

训练与模板的新建支持 `clientRequestId`，后端保留请求哈希与操作者：同一请求重试返回原记录，不同内容409，已在回收站409；并发写入仍需CAS，冲突后同请求可重试。此保护尚未覆盖其他实体和上传。新建由后端写入 athleteId/createdAt/createdBy/updatedAt/updatedBy；编辑旧训练只补归属与修改时间，不猜创建时间。完整操作审计仍待后续阶段。

迁移 `20261021131620_extend_nico_training_templates.sql` 扩展台账约束及同步函数为十二类，不重写事实库、不改变版本、不公开新集合。旧备份缺少模板集合时兼容为空；恢复仍将被旧备份遗漏的新训练/模板保留在回收站。回滚应用时保留宽约束和新字段，以向前修复处理；不得缩约束、删除模板或覆盖后续数据。

线上台账仅允许旧九集合，而应用已有 weakpoints/checkins。迁移 `supabase/migrations/20261021095107_extend_nico_practice_ledger.sql` 在原有两份 backend SQL 之后执行：事务内放宽集合检查为十一类，并替换同步函数以覆盖十一类；保持 SECURITY INVOKER、空 search_path、仅服务角色调用。没有新增公开权限，不回写业务快照、不改变 revision、不回填虚构记录。读取时兼容历史快照缺少两类集合，损坏集合仍报错。

上线前核对旧约束、函数、表权限、真实快照版本与摘要；上线后核对新约束/函数、RLS/调用权限及快照摘要不变。应用回滚时保留扩展约束和台账，避免已有新类数据无法读取；只有两类都无数据并保存函数旧定义时才可恢复旧约束，禁止删除新类记录来完成回滚。

## V1.0.1 本机草稿（不属于业务事实库）

草稿不引入数据库实体，也不改变成绩/训练计算。`nico.draft.v2`键按API地址、已验证账号、当前Nico档案及表单类型隔离；本机Cookie版以页面来源区分后端。身份只来自服务端确认结果，未登录、强制改密及只读角色不授予草稿存取。会话失效后旧自动保存引用失效。

草稿信封含version、归属、类型、createdAt/updatedAt/expiresAt及原始表单payload；保存原baseRevision、编辑ID及训练clientRequestId，网络错误不能重置这些字段。最近编辑起7天有效；过期不自动恢复或删除，明确确认续期后才能恢复。读取损坏/存储禁用时不覆盖原件，展示导出及重填提示。正式保存仍使用原服务端校验和CAS；恢复草稿不自动提交。

退出对话框明确选择保留或删除本账号本档案新版草稿；不删除其他账号和未归属旧草稿。旧固定键仅显示存在提示，家长明确确认归属后创建当前身份副本，原键保留。localStorage为设备明文，不能代替服务器权限或加密保险箱，导出文件由用户保管。
