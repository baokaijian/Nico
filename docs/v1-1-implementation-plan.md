# V1.1 技能与目标增量实施契约

基线：已独立上线的V1.0.1（7251f7d）。本文件是实施计划，不是已开发或已验收声明。先完成新实体及两后端合同，再接界面和迁移发布；不改稳定的performance.ts/training.ts计算。需求差距表中的技能/目标状态保持未完成。

## 技能模型与使用闭环

- 新增私有skillDefinitions、skillAssessments。维度固定为水中安全、呼吸及水感、自由泳、仰泳、蛙泳、蝶泳、出发和转身、训练行为；内部L1–L5仅用于个人成长记录，不能替代官方证书或独自下水的许可。
- 标准可配置，包含技能名称、维度、五级可观察标准、标准版本、适用说明及启用状态。首批提供水中安全和自由泳的可编辑内部标准模板，家长明确创建/确认后使用；不插入虚构评估。其他维度使用同一配置能力扩展，不编造统一测评距离、时间或训练处方。
- 评估包含技能/标准版本、评估日期、评估人、人工选定等级、证据及说明、当前审核状态和改进说明。服务端保存当时标准快照，后续改标准不回写历史。只有明确确认的评估进入当前能力及变化图，不从打卡次数、连续天数或训练量推算等级，也不把八维简单平均成天赋分数。
- 历史按技能查询，使用离散日期/等级点及可访问列表展示，单点不拟合趋势。已确认评估的修改/撤销留历史，不静默覆盖。
- 技能评估可作为技术短板来源；沿用现有weakpoints/checkins。支持评估→关联薄弱点→实际打卡→阶段复测，并保留复测与前评估/短板的关联，拒绝不存在或不同技能的引用。

## 目标与里程碑

- 增强既有goals，保留旧title/targetMetric/原始备注，新增起始能力或成绩、目标结果、截止日期、关联训练与技能、可验证标准、证据与确认信息。
- 五状态沿用原四态并增加完成归档：待确认、进行中、已达成、暂停、已归档。已达成须经过明确的家长确认动作，证据非空、标准明确且确认人有效；归档只能接续已确认完成。自动计算只生成候选证据，不代填人工确认。
- 历史目标保留原文、原状态和未知时间，不把旧“已达成”自动转换为新流程完成证明。增强时显式采用新流程，并保留旧版本。
- 新增私有milestones。目标人工完成后生成一个待确认里程碑，保存当时目标/证据快照；重复请求不得重复生成。候选须再次明确确认，目标后续修改不篡改既有历史事件，不自动扩大公开范围。

## 服务端、历史与恢复

- 新实体、增强目标及其关系由共享TypeScript合同验证，前端/本机/云端同一规则。元数据归属、创建/修改人和时间由服务端写入，拒绝客户端伪造；旧未知创建时间保持未知。
- 私有快照、集合、原片及写入继续认证，当前人工发布白名单保持。新标准/评估/目标/里程碑不因部署而公开。
- 对新增实体和增强目标增加服务端版本历史，记录人工确认/归档/删除/恢复；限定在本阶段范围，不宣称已实现全站独立审计。还原旧备份时合并历史并保留较新记录，版本不倒退，相同ID/版本不同内容拒绝静默覆盖。
- 逻辑删除、回收站及原片保留沿用现有机制；新引用要求存在且归属一致，历史通过标准/目标快照可解释，恢复不能制造悬空新关系。
- Postgres只增量放宽台账集合约束并扩展同步函数，不拆表、不重写事实库或补造评估。保留SECURITY INVOKER、RLS及仅服务角色调用；应用回滚后保留已扩展的约束和数据，向前修复优先。

## 分批验收与发布

1. 共享合同和历史：红/绿测试覆盖八维/五级边界、证据、确认、标准快照、未知数据、旧目标兼容及无损恢复。
2. 两后端集成：相同流程测试技能评估→短板→打卡→复测、目标→候选证据→确认→归档→待确认里程碑；访客/失效令牌拒绝，新记录版本及归属不可注入，重试幂等，删除/恢复和备份保留历史。
3. 前端：在既有打卡与档案入口扩展，保持查看/管理模式与v2草稿隔离；历史/查询/可访问变化图；四目标尺寸及键盘验收。真人60秒录入独立记录，不用自动化冒充。
4. 迁移先在事务内演练并回滚，核对快照版本/摘要/原对象不变，再部署增量迁移和API；前端在API就绪后发布。正式库不写模拟评估、成绩或训练。
5. 最后核对完整lint/typecheck/test/build、公开构建/线上访客边界及实际部署版本，统一更新差距表、测试和变更记录；明确仍未验证的真人、真机及历史隐私清理事项。

V1.0.1验收、历史隐私风险和待确认清理方案继续有效，不能因推进V1.1而将它们改写为全部完成。
