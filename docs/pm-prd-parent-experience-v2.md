## 0. 一页结论

**产品定位**：给「一个家庭 + 一位教练」使用的**游泳训练事实档案**。只记录真实发生的事，不做打分器、不做天赋预测、不做儿童排名。

**与现有仓库的关系**：功能已经完整。多运动员隔离、教练授权、周期对比、技能目标、报告、媒体与备份都已合入 `master`。本期不是重写，而是把家长每天真正会走的「今日 → 记录 → 复盘」三段路径做顺，让一个家长在手机上用更少滚动、更少字段、更少找不到，完成同一批事实记录。

**本期必须补齐的六个体验缺口**：

| 缺口 | 现状证据 | 家长感受 | 处理方式 |
|---|---|---|---|
| 工作台太长 | `src/components/Workbench.jsx` 首屏九类区块 | 打开后不知道先看哪 | 今日卡 + 渐进披露 |
| 快速录入字段偏多 | `TrainingRecords.jsx:93` 常显 5 字段；成绩非打腿仍显示 `testItem` | 在停车场单手录入慢 | 训练 4 字段、成绩 6 字段，其余折叠 |
| 搜索只到成绩 | `src/App.jsx:142-147` 无条件跳 `training/swim` | 搜训练备注/影像找不到 | 当前运动员范围全局搜索 |
| 教练反馈无入口 | `coachNotes` / `feedbackBy` 仅存在训练列表 | 错过教练原话 | 工作台反馈卡 + 回源 |
| 报告缺上下文 | `Reports.jsx:23` iframe 预览；`report-drafts.mjs:53` 无运动员头 | 不知道是哪个孩子、样本够不够 | 报告摘要卡 + 运动员头 + 固定导出条 |
| 多儿童身份不显 | `App.jsx:172-179` 顶栏一个内联 `select` | 切换后不确定当前是谁 | 当前运动员语义 + 报告/文件名贯通 + 切换确认 |

**规模假设**（决定架构，不要超配）：单家庭 ≤4 名儿童；单儿童 ≤500 条训练 / 年、≤200 条成绩 / 年；并发写 ≤3 人；单实例部署，家庭级隔离即可。

**关键非功能底线**：匿名不得写入、不得读取私有档案；未填写的测量值不得补 0；样本不足不得画趋势；公开页只能出现白名单内字段；本期**不新增公开字段**。

## 2. 产品定位与目标用户

### 2.1 一句话定位

> 家长用它记录孩子每次游泳训练的真实数据，教练用它留一句可追溯的点评，三个月后能拿出证据说明「哪里进步了、哪里还没练到」——而不是一份好看的成绩单。

### 2.2 产品边界

| 做 | 不做（写进提示词的红线） |
|---|---|
| 记录已发生的训练、成绩、身体测量、教练原话 | 生成未发生的训练计划数值、预测成绩、预测身高 |
| 按明确规则计算 PB、训练量、达成率 | 给孩子的「天赋分 / 潜力值 / 综合评分」 |
| 展示数据缺口并说明为什么不足 | 用默认值或历史外推填补缺失 |
| 家长人工确认技能等级与目标达成 | 由打卡次数自动推算等级 |
| 私有一切，家长逐条勾选才公开 | 默认公开、模糊化公开、汇总后公开 |
| 让家长更快看到、更快录入、更快回源 | 为了“好看”隐藏缺失、把未知显示成 0 |

### 2.3 用户画像

| 角色 | 系统角色 | 使用频率 | 核心诉求 | 关键约束 |
|---|---|---|---|---|
| **家长（主用户）** | `owner` | 每次训练后 1 次，周末 1 次复盘 | 45 秒内记完一次课；三个月后能看到进步证据 | 手机上单手操作；不愿被要求填 20 个字段 |
| **教练（协作）** | `coach` | 每周 1–3 次 | 只给孩子写一句技术点评和实际完成量，不碰家庭隐私 | 只能看被授权的孩子；不能导出、不能改公开设置 |
| **孩子** | `child` | 偶发 | 看自己的进步和照片 | 15 分钟受限会话，只看家长已确认内容 |
| **亲友/访客** | `viewer` | 偶发 | 看家长愿意公开的成绩和视频 | 无需登录，但不能看到任何私有字段 |

### 2.4 核心场景

| 编号 | 场景 | 触发 | 用户动作 | 成功判据 |
|---|---|---|---|---|
| S1 | **课后快速记录** | 训练结束在停车场 | 打开 → 今日卡 → 快速模式 → 填 4 字段 → 保存 | 从打开到保存 ≤45 秒（真人计时验证） |
| S2 | **补一条成绩** | 刚测完 50 自 | 今日卡次要按钮 → 快速成绩 6 字段 → 保存 | 非打腿时不出现“具体打腿项目”；有效+池长已知才进 PB |
| S3 | **周末复盘** | 周日晚 | 工作台看本周实际量、教练原话、待办 → 打开报告 | 3 屏内看完，每项可点回原记录 |
| S4 | **找一条旧记录** | 家长想起“上周教练说转身” | 顶部搜索 → 结果分组 → 打开原训练 | 训练/成绩/影像/报告都能搜到；不跨孩子 |
| S5 | **切换孩子** | 二胎家庭 | 顶栏切换 → 当前运动员标识变化 → 记录 | 无跨孩子数据；未保存草稿有明确提示 |
| S6 | **导出报告** | 季度末 | 报告页 → 摘要卡 → 导出 HTML / 打印 PDF | 报告头含运动员与周期；导出与页面一致 |

### 2.5 关键用户旅程（家长首月）

```
第 1 天   登录 → 今日卡 → 快速记录 1 次训练（4 字段）
第 1 周   每天课后 1 条 → 工作台看到「本周 3 次 / 2.4km」
第 2 周   教练被邀请 → 教练补一条点评 → 工作台「教练原话」卡出现
第 4 周   第一次测 50 自 → 快速成绩 6 字段 → 有效+池长已知 → PB
第 8 周   第一次技能评估（家长人工定级 L1–L3）→ 目标「50 自进 40 秒」
第 12 周  季度报告：摘要卡 → 导出 PDF → 报告头显示孩子姓名与周期
```

**关键设计判断**：第 1 周必须让家长只填 4 个字段就能完成一次训练记录。字段全部展开的表单会让首周流失；这是本产品最大的流失点。

## 3. 功能范围

### 3.1 范围决策

| 层级 | 包含 | 理由 |
|---|---|---|
| **P0（本期必须）** | 今日卡、工作台渐进披露、快速训练 4 字段、快速成绩 6 字段、保存后下一步条、教练反馈卡、当前运动员全局搜索、多儿童身份贯通、报告摘要/阅读/导出、五态、390px/无障碍、性能预算、验收文档 | 直接决定家长每天是否愿意打开 |
| **P1（下期）** | 记录时间线按月分组、数据完整度卡、报告章节导览、公开页署名的显式授权、教练端 UI 重做 | 提效与扩展，可在本期验收后单独排期 |
| **不做** | 机构多租户、班级/学员批量管理、付费订阅、AI 生成训练计划、成绩预测、儿童排名、社交 feed、可穿戴设备直连、小程序端、新第三方依赖 | 与「事实档案」定位冲突，或超出单家庭规模 |

### 3.2 P0 功能清单

> 复用列：`复用` = 现有代码可直接用；`改造` = 在现有代码上改；`新增` = 需新写。

#### A. 今日与工作台

| 编号 | 功能 | 复用 | 验收标准 |
|---|---|---|---|
| FR-PX-01 | **今日卡**：当前运动员、今天是否已记录、本周次数/已知时长/已知距离、主按钮「记录这次训练」、次要「记录成绩」、最近 1 条教练原话、前 3 条待办 | 改造 `Workbench` + 新增 `TodayCard` | 首屏可见；缺失显示「未记录」；今天没有记录时不显示 0；主按钮始终可点；不预填任何实际值 |
| FR-PX-02 | **工作台渐进披露**：默认只显示今日卡、本周摘要、待办、当前重点；目标/最近训练/成绩变化收进「更多」；390px 默认折叠，按运动员记忆展开状态 | 改造 `Workbench` | 默认首屏高度 ≤2 屏；「更多」可展开/收起；展开状态只存 sessionStorage，不写业务事实；新运动员默认折叠 |

| 编号 | 功能 | 复用 | 验收标准 |
|---|---|---|---|
| FR-PX-04 | **快速训练 4 字段**：日期、实际时长、实际距离、完成情况常显；训练内容优先用「最近使用」chip 一键选择，没有最近内容时放在补充字段；感受/备注/RPE/训练组/影像/计划关联折叠为补充 | 改造 `TrainingRecords` + `record-form.js` | 常显字段恰为 4 个；最近内容 chip 只设 `trainingType`，不填实际值；切换训练组时才显示组表；保存路径不超过 4 个输入动作 |

### 4.4 关键交互流程

**流程 1：打开 → 记录一次训练**

```
工作台 → 今日卡「记录这次训练」→ 快速训练 4 字段
 → 保存成功 → 下一步条
 → 选择「结束」或补充成绩/影像/反馈
异常：离开 → 草稿保留 → 回来提示「有未完成草稿」
```

**流程 2：保存冲突**

```
用户点保存
 ├─ 200 → 关闭表单，列表就地插入，显示「已保存」
 ├─ 409 → 表单不关闭、不清空；黄条「另一台设备已修改」
 │        [查看最新] [用我的版本覆盖] [已核对最新，允许重试]
 ├─ 0（网络）→ 红条「未确认是否写入，请刷新核对后再重试」
 │            保留草稿；不自动重试
 └─ 401 → 提示重新登录，草稿保留
```

**流程 3：搜索**

```
顶部输入 → 回车
 → 有结果：按训练/成绩/影像/报告分组；每条可回源
 → 无匹配：显示「没有匹配的记录」+ 清除搜索
 → 当前运动员无任何记录：显示「还没有可搜索的记录」
 → 切换运动员/退出：清空搜索
```

**流程 4：切换运动员**

```
点击顶栏切换器
 ├─ 有未保存草稿或打开快捷录入
 │   → 确认「草稿按原运动员保留，切换后不自动提交」
 │   → [取消] 留在原运动员；[继续切换] 切换
 └─ 无草稿 → 直接切换；清空搜索；重算所有投影
```

**流程 5：报告导出**

```
选择报告 → 摘要卡 → 预览
 ├─ 待确认 + 未过期 + 叙事已保存 → [人工确认报告]
 ├─ [导出 HTML] → 文件名含运动员/周期
 ├─ [打印 PDF] → iframe 加载完成后可用
 └─ 来源变化 → 显示「已过期」，保留旧事实，不静默覆盖
```

### 4.5 状态矩阵（P0 页面逐页实现）

| 状态 | 表现 | 禁止 |
|---|---|---|
| 加载中 | 骨架屏，保留上次内容轮廓；`aria-busy="true"` | 空白页 + 转圈超过 1 秒 |
| 空（从未录入） | 「还没有记录。记一次今天的训练 →」 | 填示例数据 |
| 空（筛选无结果） | 「没有符合筛选的记录。清除筛选」 | 与「从未录入」同一文案 |
| 读取失败 | 有上次数据时「读取失败，显示的是上次成功的数据」+ 重试；无数据时说明原因 + 重试 | 伪装成空数据 |
| 保存中 | 按钮 loading 且禁用重复提交 | 允许双击产生两条 |
| 保存成功 | 轻提示 + 列表就地更新 | 整页刷新丢滚动位置 |
| 冲突 409 | 黄条 + 查看最新 + 覆盖（二次确认）+ 已核对重试 | 静默覆盖 |
| 未提交草稿 | 顶部常驻「有未保存草稿」+ 继续/丢弃 | 自动提交 |
| 样本不足 | 「仅 1 条有效记录，不足以判断趋势」 | 画一条直线 |
| 无权限 | 「此操作仅限家长管理者」 | 隐藏按钮但不拦接口 |
| 媒体处理中 | 「处理中，请保持页面打开」 | 标成「已处理」 |

### 5.4 并发与版本（沿用，不改）

- 读：返回 `X-Nico-Revision` 响应头，前端记住。
- 写：必须带 `If-Match: <revision>`；不匹配返回 409 + 当前版本摘要。
- 新建：带 `clientRequestId`（UUID），服务端存请求哈希；同哈希重试返回原记录，不同内容返回 409。
- 冲突处理：不静默合并、不静默覆盖；用户在「查看最新」与「覆盖」之间显式选择。
- 快照：版本化 JSON 业务状态 + 台账表；台账只追加，不 UPDATE 业务事实。

### 5.5 迁移策略

**本期无数据库迁移、无新集合、无新公开字段。** 所有改动是前端展示层与新纯投影。若实现中发现必须迁移，停止并回到产品确认，不自行扩大范围。

- 不用「战力」「天赋」「潜力」「突破」「保证」「一定能」。
- 鼓励指向过程：「这周比上周多游了 400 米」，而不是「进步很大」。
- 报错必须说明「发生了什么 + 数据现在在哪 + 下一步怎么做」，不能只说「操作失败」。
- 搜索/摘要/报告中的缺失：写「未记录」，不写「0」或「无」。
