## 已实现的防再发生能力

- `scripts/check-repository-privacy.mjs`：工作区、暂存区和待推送提交的可达历史检查；私人路径、数据库/密钥/备份、常见凭据模式、非空档案JSON、符号链接和未经清单批准的媒体拒绝（包含提交后删除的历史媒体）；超过文本检查上限明确拒绝，不静默放行。输出只有规则、位置和行号，不输出匹配值。不是所有未知秘密或影像内容的完整识别器。
- `security/public-assets.json`：现有授权摘要及6个播放/封面文件的SHA256，另固定已公开的开源字体。historicalFiles只列已核对的旧摘要格式与不含人物的旧几何装饰图；不允许用这些历史例外修改当前文件。素材或摘要改变必须先取得对应公开授权，再人工更新清单；不能用自动重建清单绕过审核。
- `.githooks/pre-commit` 检查真实暂存字节，`.githooks/pre-push` 检查每个实际推送提交的历史，避免把本机保留的旧历史再次公开。`npm run security:hooks`在当前checkout启用；新clone也需执行。CI是独立保护，不能只依赖可绕过的本机hook。
- Pages/API构建在部署前检查当前提交的完整可达历史；checkout不持久化GitHub凭据。`npm run check`新增全仓库门禁，不能以构建目录白名单代替源码安全。
- `tests/fixture.mjs`始终为合成协议数据，去掉读取真实本机seed的默认路径；现有真实数据只读审计工具仍独立使用。
- `backup-job`所有输出均拒绝落在仓库内，包含之前遗漏的src/keys及路径别名，末级文件拒绝软/硬链接，密钥禁止覆盖；输出文件权限0600，目录0700。旧备份格式、加密、验证、恢复和真实档案不改变。
