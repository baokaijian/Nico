# Nico Growth V1.2 管理端体验设计与操作审查

日期：2026-10-22。代码审查基线：master fa0169b（V1.1）。本文件先于产品代码修改输出；用户已明确要求先输出方案再执行。保留React 19/Vite、现有API、认证、共享计算和实体；在适配层增量重组。不以自动化宣称45秒真人录入达成。

## 1. 当前操作路径矩阵

口径：从已登录「今日」开始；“入口操作”只数按钮/页签/折叠的显式激活，不数输入字段、滚动、选文件系统对话框或网络等待；“提交”是业务写接口次数。下表是代码路径审查，不冒充真人测量，按所选分支计数，页面组件数量不等于点击数。

| 业务 | 当前路径与入口操作 | 必填与常见输入 | 提交 | 额外确认 | 保存后的下一步/断点 |
|---|---|---|---|---|---|
| 基础训练 | 今日「记录本次训练」1次可展开；或记录→添加训练2次 | 日期；常用时长、距离、内容、泳姿、完成情况（后端允许未知，不补造量） | 1 | 新录入无；替换未保存表单须确认 | 成功后仅有影像关联按钮；添加成绩、反馈需另找入口 |
| 训练后补成绩 | 记录→成绩→添加记录3次；从训练页开始2次 | 日期、距离、泳姿、池长、成绩；打腿还需具体项目；计时方式/出发/性质/有效性 | 1 | 非有效不计PB，不要求无意义确认 | 无训练ID关联，没有同次活动摘要；回训练需换类型 |
| 使用训练安排 | 记录→复制上次安排2次；使用模板需找到模板；高级计划关联需展开与选择 | 本次实际量、日期/完成情况；不复制实际组数 | 1 | 替换当前输入、带入计划并清空实际须确认 | 原计划版本保留，但训练/计划入口分开 |
| 上传训练视频 | 训练保存→为此次关联影像1次，跳至复盘；普通入口复盘→录像复盘→上传素材3次 | 日期、标题、文件；关联项已预选时无需再选 | 原片1；云端副本处理另1或失败状态1 | 选文件；不公开 | 仍停留在相册，原片与处理状态反馈混杂，不能回到活动摘要 |
| 已有影像关联 | 保存训练→影像→勾选素材→保存关联 | 实际素材选择 | 1 | 保留原素材主关联 | 不应误改素材原recordId；现已有mediaIds复用 |
| 追加教练原话 | 记录→编辑训练→展开感受/反馈3次左右 | 教练原话，其他原值保留 | 1 | CAS冲突须刷新核对 | 完成后仍在长列表，需再找后续事项 |
| 技能测评 | 打卡→技能测评与标准→记录本次测评3次 | 标准、日期、评估人、人工等级、观察证据；改进/引用可选 | 保存1，人工确认另1 | 必须另填确认人/说明 | 八维空卡和说明在表单前；标准配置也在本页 |
| 标准配置 | 打卡→技能→配置标准→采用模板4次 | 五级标准、技能名/维度、审核人和启用状态 | 1 | 启用需审核人 | 低频配置与日常测评竞争入口 |
| 测评→短板→打卡→复测 | 测评人工确认后关联短板（切回练习）→保存→打卡→进入复测→再预填 | 短板核对、真实打卡次数/质量、复测等级/证据 | 短板1、打卡1、复测1、确认1；前测另2 | 等级/证据确认保留；预填不代测评 | 上下文已有部分预填，但子页切换/长距离滚动打断闭环 |
| 目标→完成→里程碑 | 档案→建立目标2次；找目标→对照证据→查看候选→选择→确认；再找事件确认 | 起点、结果、截止、标准；完成证明、确认人/说明；里程碑独立确认人/说明 | 建目标1、达成1、归档1、事件确认1 | 达成和里程碑是两个独立人工动作 | 同页已有数据，但夹在基础档案/官方表/发布/备份之间，缺连续审核提示 |
| 周期计划 | 本周→展开编辑；可从草稿创建 | 周期/重点/状态/复核人和真实计划课次 | 每版本1 | 计划确认必须明确复核人；版本冲突保留 | 长页先规则解释，实际课次与历史混在一起 |
| 周期报告/视频批注 | 复盘→周期报告或录像复盘；批注需再展开 | 周期；视频运动员/泳道、时间段、观察及审核 | 报告只读；批注每条1 | 技术观察审核保留 | 不能用组件数当点击数；时间点选择、视频处理本身有真实成本 |
| 发布/备份/回收 | 档案→滚动至对应区 | 人工白名单/发布人/日期；备份文件 | 发布/恢复各1 | 备份恢复确认；发布选择明确人工完成 | 低频管理和高频目标竞争；用户容易误以为已保存=已公开 |

审查覆盖App、Dashboard、TrainingRecords、Records、Practice、Skills、GrowthGoals、PlanViewer、MediaGallery、Profile、src/services及shared。核心performance.ts/training.ts不重写。发现成绩创建与原片上传缺少稳定创建收据；V1.2连续流程上线前必须补齐两个后端，不能仅隐藏重复按钮。

## 2. 导航与旧新功能映射

| 新一级入口 | 二级区域 | 旧功能来源/复用方式 |
|---|---|---|
| 工作台 | 四快捷操作、真实待确认、训练重点、本周摘要、进行中目标、最近训练/成绩 | 新轻量Workbench，使用既有共享分析选择器；Dashboard保留为趋势详情 |
| 训练记录 | 日常训练、成绩、训练计划、影像关联 | TrainingRecords、Records(swim)、PlanViewer、MediaGallery；按区域适配，不整页重写 |
| 成长管理 | 技能工作区、技术短板/练习、阶段目标/里程碑 | Skills、Practice、GrowthGoals；围绕选定技能联动，在同一管理工作区切换上下文面板 |
| 分析复盘 | 历史趋势、周期报告、视频技术复盘、成长档案 | Dashboard的历史趋势详情、Reports、MediaGallery、身体/体能/恢复记录与只读档案 |
| 账号菜单→管理设置 | 基础档案、公开展示、备份与回收、技能标准配置 | Profile分区适配、Skills配置区域；家长角色保持，协作角色不能因此获得发布/备份/测评写权限 |

旧navigate('today'/'week'/'practice'/'records'/'review'/'profile')通过映射解析到新位置，现有组件按钮继续工作。新导航使用白名单路由对象；上次管理位置按API/已验证账号/档案写入sessionStorage，只存导航，不存业务事实。登录确认后恢复，退出/账号切换不串位置，非法或失效区域回工作台。浏览/返回遵循本次标签页的管理位置；公开模式保持原三入口及匿名白名单。

手机四个一级入口直接可用；底部固定「快捷录入」入口展开四项选择，并给内容留安全区空间。桌面快捷区在工作台顶部。只读用户查看各区，录入入口按权限禁用/隐藏。查看模式明确标注“仅授权公开内容”，管理模式标注“完整档案”，不自动扩大公开范围。

## 3. 工作台原型与视觉原则

沿用品牌的水蓝/青色和现有字体，不换全站视觉体系。基色#F5F7F6，主文#19313D，品牌#126E82，辅助#607780，边线#D7E1E2，成功#27684A；系统中文无衬线，标题24–28px、正文16px、辅助14px。内容左对齐，单列阅读宽度约72字符。重点只给快捷操作，其他内容以有层次的区块/分隔线组织，不为每条说明新增装饰卡。

```text
┌ 工作台 | 训练记录 | 成长管理 | 分析复盘       刷新  账号 ┐
│ 管理模式 · 完整档案（公开展示需在管理设置单独选择）       │
│ 工作台                                                  │
│ [记录训练] [记录成绩] [技能测评] [添加影像]                │
│ 未完成录入可继续（仅确有本账号草稿时出现）                │
│ 待确认事项 N           当前训练重点  [详情]              │
│ · 测评待确认 [处理]     已确认重点或明确标为待确认建议     │
│ · 目标待确认 [处理]                                      │
│ · 里程碑待确认 [处理]                                    │
│ 本周训练摘要  次数 / 已知分钟 / 已知米 [详情]             │
│ 进行中成长目标  最多3项 [全部]                            │
│ 最近训练 [详情/继续补充]   最近成绩变化 [趋势详情]         │
└ 手机：四一级入口 + 固定快捷录入入口，触控至少44px          ┘
```

待办只来自待确认测评、待确认目标、待确认里程碑和待确认技术短板；不因打卡中断或数值低而造任务。计划草稿仍是待复核建议，不自动冒充任务或确认计划。首页只显示数量和简要标题，来源、规则、完整历史都在详情/折叠内。

## 4. QuickEntry与连续录入原型

统一QuickEntry容器：桌面模态窗，手机全高可滚动面板，标题/关闭与状态反馈清楚；一次只显示一种表单。使用现有表单的entryOnly/initialContext/onRecordSaved适配接口，不复制一整套校验。

```text
记录训练                                   [暂存并关闭]
日期           训练内容
实际分钟       实际距离（任选已知量填写，未知可留空）
完成情况       最近使用内容快捷选项
▸ 高级：训练组、泳姿、RPE、教练反馈、计划版本关联
[保存训练]

✓ 本次训练已保存到私有档案
日期/实际完成摘要
[添加成绩] [上传视频/关联已有影像] [记录教练反馈] [结束]
  └ 后续一步成功/失败均返回或可返回本次摘要；主记录不回滚
```

成绩：日期、项目/泳姿/距离/池长、真实成绩、出发与计时条件、记录性质和有效性；默认未核验，不填旧成绩。选打腿时具体项目就在主区并必填。训练上下文只带入已保存训练ID、日期及明确存在的泳姿，成绩值为空。必要新增swim.trainingId可选关联字段，旧数据保持无关联，不推测补写。成绩表单显示可读训练标签，不让家长输入ID。

技能：可预选最近使用且仍启用的技能标准/当前版本；日期默认今天，等级/观察证据为空，评估人由人填；保存和人工确认保持分开。标准全文折叠可查。

影像：日期、标题、原文件和可读关联选择器；已有训练上下文预选recordId，不改变原有素材主关联；添加已有素材复用training.mediaIds。原片保存成功与副本处理失败分别反馈。上传后回本次完成摘要，播放副本失败可稍后重试；不删除主训练或原片。

关闭/切页/刷新：业务表单继续用现有7天身份草稿；连续流程状态另存同一身份下的本机工作流草稿，记录已确认主记录ID、后续完成ID、当前步骤和稳定请求ID。它不是另一份事实库。恢复先核对当前服务端记录，主记录在回收站或不存在时阻止继续，不能静默新建替代。浏览器不缓存视频字节；刷新后需重选原文件并核对重试。主记录成功后可随时结束，不能把跳过的步骤算失败或阻止退出。

创建成绩补充clientRequestId收据，原片上传补充相同能力（服务端根据元数据+文件SHA256计算内容哈希），两后端在CAS前检查已完成请求：同内容返回同一记录，变内容/已删除拒绝；并发仍CAS。未确认上传结果先刷新核对并用原请求重试，不生成新ID。不会重写旧业务记录或改核心成绩/训练计算；JSON台账已支持现有集合，无需破坏性迁移。

反馈是对已保存训练的明确PUT，保留开始输入时的CAS版本和其他事实字段；冲突保留输入，刷新后人工采用新版本。主训练、成绩、素材是独立事务，完成摘要分别列出状态；任何后续失败都不得撤销前一步成功。

## 5. 技能详情与目标审核工作区

```text
成长管理    [技能工作区] [阶段目标与里程碑] [全部练习]
技能选择：自由泳动作配合（实际标准）
已确认L2  / 标准v1 / 日期      [本次测评]
[测评与历史] [技术短板与打卡] [关联目标]
测评证据/历史（按需展开）
[确认后建立短板] → 本区域预填短板 → 保存 → 打卡
[关联打卡发起复测] → 本区域预填前评估/短板/打卡
等级、证据仍为空；明确测评后保存，另行人工确认
```

不同实体独立保存。仅把明确关联同一技能的记录放入技能工作区；未关联短板/目标仍在全部练习/全部目标，不擅自猜关联。当前能力只取已确认测评，标准/历史版本始终可查。工作区内操作切换上下文面板并定位表单，避免顶层模块往返。已有未处理草稿阻止覆盖，提供恢复/导出；不能用强制重挂组件绕过草稿。

目标面板：候选列表→家长选择证据→确认达成（第一独立人工动作）→展示目标已完成及待审核里程碑→点击审核里程碑（第二独立人工动作）→可选目标归档。同页内完成，绝不自动勾选证据或连续自动确认。归档、重新开启、撤销仍留版本历史。所有新成长事件保持私有。

| 阶段 | 主要文件 | 实现/风险 | 验证 | 回滚 |
