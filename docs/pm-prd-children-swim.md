## 0. 一页结论

**产品定位**：给「一个家庭 + 一位教练」使用的**游泳训练事实档案**。只记录真实发生的事，不做打分器、不做天赋预测、不做儿童排名。

**与现有仓库的关系**：当前仓库已是一个可运行、可发布的**单儿童版本**（运动员 ID 硬编码为 `nico`，角色实际只有 `owner` / `viewer` / `child`）。本 PRD 把它产品化为「多儿童 + 双角色协作」的可交付版本。

**必须补齐的三个缺口**（这是本 PRD 的主要增量，不是重写）：

| 缺口 | 现状证据 | 影响 | 处理方式 |
|---|---|---|---|
| 多运动员隔离 | `server/cloud-api.mjs:147` 返回 `athleteId: 'nico'` | 一个账号只能管一个孩子，二胎家庭无法使用 | 全链路引入 `athleteId` 作用域，快照按运动员拆分 |
| 教练协作角色 | `src/App.jsx` 有 `coach: '协作录入'` 文案，但鉴权只判 `owner` | 教练无法安全录入，也不能只授权单个孩子 | 新增 `coachGrants` 授权表 + 服务端逐请求校验 |
| 跨周期对比统计 | 现有分析以单周期为主 | 家长看不到「三个月前后」的变化 | 新增周期对比投影（纯计算，不新增事实库） |

**规模假设**（决定架构，不要超配）：

- 单家庭 ≤ 4 名儿童；单儿童 ≤ 500 条训练 / 年、≤ 200 条成绩 / 年。
- 并发写 ≤ 3 人（家长 + 教练 + 另一台设备）。
- **不做**机构多租户、不做班级管理、不做付费订阅。单实例部署，家庭级隔离即可。

**关键非功能底线**：匿名请求不得写入、不得读取私有档案；未填写的测量值不得补 0；样本不足不得画趋势；公开页只能出现白名单内的字段。

## 1. 技术资产盘点（复用基础）

### 1.1 技术栈

| 层 | 实现 | 关键约束 |

| 测试 | `node --test`，62 个测试文件；`npm run check` 串起隐私检查/lint/typecheck/test/build/verify | 任何提交前必须全绿 |

## 2. 产品定位与目标用户

### 2.1 一句话定位

> 家长用它记录孩子每次游泳训练的真实数据，教练用它留一句可追溯的点评，三个月后能拿出证据说明「哪里进步了、哪里还没练到」——而不是一份好看的成绩单。

### 2.2 产品边界

| 做 | 不做（明确拒绝，写进提示词） |
|---|---|
| 记录已发生的训练、成绩、身体测量、教练原话 | 生成未发生的训练计划数值、预测成绩、预测身高 |
| 按明确规则计算 PB、训练量、达成率 | 给孩子的「天赋分 / 潜力值 / 综合评分」 |
| 展示数据缺口并说明为什么不足 | 用默认值或历史外推填补缺失 |
| 家长人工确认技能等级与目标达成 | 由打卡次数自动推算等级 |
| 私有一切，家长逐条勾选才公开 | 默认公开、模糊化公开、汇总后公开 |

### 2.3 用户画像

| 角色 | 系统角色 | 使用频率 | 核心诉求 | 关键约束 |
|---|---|---|---|---|
| **家长（主用户）** | `owner` | 每次训练后 1 次，周末 1 次复盘 | 45 秒内记完一次课；三个月后能看到进步证据 | 手机上单手操作；不愿被要求填 20 个字段 |
| **教练（协作）** | `coach` | 每周 1–3 次 | 只给孩子写一句技术点评和实际完成量，不碰家庭隐私 | 只能看被授权的孩子；不能导出、不能改公开设置 |
| **孩子** | `child` | 偶发 | 看自己的进步和照片 | 15 分钟受限会话，只看家长已确认内容 |
| **亲友/访客** | `viewer` | 偶发 | 看家长愿意公开的成绩和视频 | 无需登录，但不能看到任何私有字段 |
| **机构/泳队** | — | — | 批量管理学员 | **本期不做** |

### 2.4 核心场景（按优先级）

| 编号 | 场景 | 触发 | 用户动作 | 成功判据 |
|---|---|---|---|---|
| S1 | **课后快速记录** | 训练结束在停车场 | 打开→快速模式→填时长/距离/感受→保存 | 从打开到保存 ≤ 45 秒（真人计时验证） |
| S2 | **周末复盘** | 周日晚 | 看本周实际量、计划覆盖率、本周最好成绩 | 3 屏内看完，每项数据可点回原记录 |
| S3 | **教练点评** | 教练下课后 | 教练登录→选中孩子→写点评+实际完成量 | 家长次日看到「教练原话」标记，不可被家长改写 |
| S4 | **比赛成绩** | 比赛当天 | 录成绩（含池长、计时方式、有效性）+ 关联赛事 | 有效成绩自动进 PB，失格单独标注且不计 PB |
| S5 | **长期进度** | 季度末 | 看技能评估变化、目标达成、年度报告 | 报告可导出 PDF，含数据范围与来源指纹 |
| S6 | **亲友查看** | 家长主动分享 | 家长勾选公开项→生成链接 | 访客无需登录，只看到勾选项 |

### 2.5 关键用户旅程（家长首月）

```
第 1 天   注册 → 建孩子档案（姓名/生日/身高体重/主项）→ 首次引导五步
第 1 周   每天课后录 1 条训练 → 周末看到「本周 3 次 / 2.4km」
第 2 周   教练被邀请 → 教练补一条点评 → 家长看到「教练原话」
第 4 周   第一次测 50 自 → 录入成绩 → 系统判定 PB（有效 + 已知池长）
第 8 周   第一次技能评估（家长人工定级 L1–L3）→ 目标「50 自进 40 秒」
第 12 周  季度报告：训练量趋势 + 技能变化 + 目标进度 → 导出 PDF
```

**关键设计判断**：第 1 周必须让家长只填 4 个字段就能完成一次记录。字段全部展开的表单会让首周流失，这是本产品最大的流失点。

## 3. 功能范围

### 3.1 范围决策

| 层级 | 包含 | 理由 |
|---|---|---|
| **MVP（P0）** | 账号与角色、多儿童档案、训练记录、成绩与 PB、周/月统计、公开展示（白名单）、数据可靠保存与备份 | 没有这些，产品不成立 |
| **P1** | 技能评估、目标与里程碑、教练授权、报告导出、媒体上传与复盘 | 决定留存与差异化 |
| **P2** | 周期对比、年度纪念册、教练点评汇总、训练模板 | 提效，可延后 |
| **不做** | 机构多租户、班级/学员批量管理、付费订阅、AI 生成训练计划、成绩预测、儿童排名、社交feed、可穿戴设备直连、小程序端 | 与「事实档案」定位冲突，或超出单家庭规模 |

### 3.2 功能清单

> 优先级：P0 = MVP 必须；P1 = 第二里程碑；P2 = 可延后。
> 复用列：`复用` = 现有代码可直接用；`改造` = 在现有代码上改；`新增` = 需新写。

#### A. 账号与权限

| 编号 | 功能 | 优先级 | 复用 | 验收标准 |
|---|---|---|---|---|
| FR-A1 | 邮箱+密码注册/登录，密码强度校验，首次登录强制改密 | P0 | 改造 `LoginPanel` / `accounts.mjs` | 弱密码被拒并给出具体规则提示；首登未改密时任何业务接口返回 403 |
| FR-A2 | 会话 1 小时有效，刷新页面可恢复，关闭标签页失效；服务端可撤销 | P0 | 复用 `session.js` | 手动撤销后旧令牌 5 秒内失效；断网不误判为登出 |
| FR-A3 | 角色 `owner` / `coach` / `child` / `viewer`，服务端逐请求鉴权 | P0 | 改造 `cloud-api.mjs` | 用 `coach` 令牌调删除接口必须 403，且返回中文原因 |
| FR-A4 | 教练邀请：家长生成一次性邀请码（24h 有效），教练注册后绑定并指定可访问的孩子 | P0 | 新增 `coachGrants` | 邀请码用一次即失效；过期码返回明确提示 |
| FR-A5 | 教练权限范围：可读授权孩子的训练/成绩/媒体；可写训练记录、成绩、教练点评；**不可**改档案、改公开设置、删除、导出全量 | P0 | 新增 | 逐项接口测试：6 项越权操作全部 403 |
| FR-A6 | 家长可随时撤销教练授权，撤销即时生效 | P0 | 新增 | 撤销后教练下一次请求返回 403 并提示「授权已被撤销」 |
| FR-A7 | 孩子受限会话：家长生成 15 分钟临时会话，仅可读已确认内容 | P1 | 复用 `child-view` | 超时后自动退出；不能通过改 URL 访问管理页 |

#### B. 运动员档案

| 编号 | 功能 | 优先级 | 复用 | 验收标准 |
|---|---|---|---|---|
| FR-B1 | 新建/编辑儿童档案：昵称、生日、性别（可不填）、身高、体重、主项、泳池常用池长 | P0 | 改造 `Profile` | 生日与性别留空可保存，且界面显示「未填写」而非默认值 |
| FR-B2 | 家庭内多儿童，顶部可切换当前运动员 | P0 | 新增 | 切换后所有列表、统计、表单作用域随之切换，无跨孩子数据 |

#### C. 训练记录

| 编号 | 功能 | 优先级 | 复用 | 验收标准 |
|---|---|---|---|---|
| FR-C1 | **快速模式**：日期（默认今天）、实际时长、实际总距离、感受、备注 | P0 | 复用 `TrainingRecords` | 4 个必填可见，其余折叠；真人计时 ≤ 45 秒 |

| FR-C3 | 完成状态：已完成 / 部分完成 / 未完成 / 已取消 | P0 | 复用 `training.ts` | 未完成/取消不允许填正的实际量；已完成组表不可缺次数 |
| FR-C4 | 教练点评字段（原话照录），标注来源为教练、带作者与时间 | P0 | 改造 | 教练写入的点评家长不可编辑，只可追加 |
| FR-C5 | 训练记录列表：按日期范围、泳姿、距离、完成状态筛选；空列表区分「未录入」与「无匹配」 | P0 | 复用 | 两种空态文案不同 |
| FR-C6 | 训练模板：保存参考安排，一键套用；套用后实际量必须清空 | P1 | 复用 `trainingTemplates` | 套用后实际次数为空，不继承模板的历史实际值 |
| FR-C7 | 复制上一条训练 | P1 | 复用 | 日期重置为今天，实际量、感受、媒体、ID 全部重置 |
| FR-C8 | 训练日历：月视图区分「计划 / 休息 / 实际完成」 | P2 | 复用 `TrainingCalendar` | 三种状态不能只靠颜色区分，需有形状或文字 |

#### D. 成绩与 PB

| 编号 | 功能 | 优先级 | 复用 | 验收标准 |
|---|---|---|---|---|
| FR-D1 | 成绩录入：距离、泳姿、池长、成绩、出发方式、计时方式、记录性质、有效性、日期 | P0 | 复用 `FIELDS.swim` | 成绩以整数毫秒存储，显示 `mm:ss:cc`；输入 56.171 秒保存后仍为 56171ms |
| FR-D2 | PB 判定：仅「有效 + 池长已知 + 同距离/泳姿/池长」参与 | P0 | 复用 `performance.ts` | 失格、无效、池长「其他」均不进 PB；跨池长不合并 |
| FR-D3 | 成绩时间线，同项目内比较差距，不跨项目换算 | P0 | 复用 `Records` | 差距标注比较对象与项目，不出现跨项目百分比 |
| FR-D4 | 赛事关联：一次比赛关联多条成绩 + 证书照片 + 名次 | P1 | 复用 `competitionEvents` | 只能关联同日同池长成绩；不允许补造历史赛事 |
| FR-D5 | 参考标准对照（二级/三级线），标注标准版本与来源 | P1 | 复用 `domain.mjs` 的 `WOMEN_50` 等 | 未内置的项目显示「请查官方完整表」，不猜测 |
| FR-D6 | 成绩有效性待确认队列（历史记录缺有效性时人工裁决） | P1 | 复用 `ScoreDecision` | 未经裁决的成绩不参与 PB，显示「未核验」 |

#### E. 进度跟踪

| 编号 | 功能 | 优先级 | 复用 | 验收标准 |
|---|---|---|---|---|
| FR-E1 | 技能评估：8 维、L1–L5 可观察标准，由家长配置并人工定级 | P1 | 复用 `growth-model.ts` | 评估必须含评估人、日期、依据；等级不可由打卡数推算 |
| FR-E2 | 技能评估变化图（仅显示已确认评估） | P1 | 复用 | 只有 1 次评估时显示「样本不足」，不画趋势线 |
| FR-E3 | 目标管理：类型（成绩/技能/习惯/比赛/自定义）、基线、目标值、截止日、状态机 | P1 | 复用 `goals` | 达成必须有确认人 + 说明 + ≥1 条证据；否则停在「待确认」 |

#### F. 统计与报告

### 4.4 关键交互流程

**流程 1：首次上手（目标：5 分钟内产生第一条有价值数据）**

```
注册 → 建孩子档案（仅昵称必填）→ 引导第 1 步「录入最近一次训练」
  → 快速模式（4 字段）→ 保存成功 → 显示「本周 1 次」并给出下一步
异常：中途离开 → 草稿保留 7 天 → 回来提示「有未完成草稿，是否继续」
```

**流程 2：保存冲突（最高频的挫败点，必须处理好）**

```
用户点保存
 ├─ 200 → 关闭表单，列表顶部插入新记录，显示「已保存」
 ├─ 409 → 表单不关闭、不清空，顶部黄条：
 │        「这条记录在另一台设备上已被修改。请先查看最新版本。」
 │        [查看最新] [用我的版本覆盖]   ← 覆盖需二次确认
 ├─ 0（网络）→ 红条「未确认是否写入。请刷新核对后再重试。」
 │            并保留草稿；不自动重试
 └─ 401 → 提示重新登录，草稿保留
```

**流程 3：公开分享**

```
家长进入「公开展示」→ 逐条勾选成绩/影像（默认全不选）
  → 填写公开标题 → 确认发布 → 生成只读链接
  → 访客打开：无登录框，只有勾选项；未勾选时整页显示说明，不填示例数据
撤回：取消勾选 → 公开页 1 分钟内消失 → 已分享的链接显示「内容已更新」
```

**流程 4：教练授权**

```
家长「教练授权」→ 生成邀请码（24h）→ 复制发给教练
教练打开链接 → 注册/登录 → 自动绑定 → 家长在列表里看到「待确认」
  → 家长选择可访问的孩子 + 权限范围 → 确认
撤销：家长点撤销 → 立即生效 → 教练下次请求 403
异常：邀请码过期 → 提示「邀请已过期，请让家长重新生成」
```

**流程 5：成绩进 PB**

```
录入成绩 → 校验池长/有效性
 ├─ 有效 + 池长已知 + 同项目无更优 → 标记「新 PB」并写入里程碑候选
 ├─ 有效 + 非最优 → 正常入库，显示与 PB 差距
 ├─ 失格/无效 → 正常入库，标红「不计 PB」，需填原因
 └─ 池长「其他」→ 入库但不参与 PB，提示「池长未知，无法跨池比较」
```

### 4.5 状态设计矩阵（每个数据页面都必须实现）

| 状态 | 表现 | 禁止 |
|---|---|---|
| 加载中 | 骨架屏，保留上一次内容轮廓 | 空白页 + 转圈超过 1 秒 |
| 空（从未录入） | 「还没有记录。记一次今天的训练 →」 | 填示例数据 |
| 空（筛选无结果） | 「没有符合筛选的记录。清除筛选」 | 与「从未录入」同一文案 |
| 读取失败 | 红条「读取失败，显示的是上次成功的数据」+ 重试 | 伪装成空数据 |
| 保存中 | 按钮 loading 且禁用重复提交 | 允许双击产生两条 |
| 保存成功 | 轻提示 + 列表就地更新 | 整页刷新丢滚动位置 |
| 冲突 409 | 黄条 + 查看最新 + 覆盖（二次确认） | 静默覆盖 |
| 未提交草稿 | 顶部常驻「有未保存草稿」+ 继续/丢弃 | 自动提交 |
| 样本不足 | 「仅 1 条有效记录，不足以判断趋势」 | 画一条直线 |
| 无权限 | 「此操作仅限家长管理者」 | 隐藏按钮但不拦接口 |
| 处理中（媒体） | 「处理中，请保持页面打开」 | 标成「已处理」 |

### 4.6 响应式规则

| 断点 | 布局 |
|---|---|
| < 480px（主目标 390px） | 单列；顶部导航收为「当前页 + 菜单」；表单字段全宽；保存按钮吸底；不依赖横向滑动的标签页 |

### 5.4 业务不变量（实现时必须逐条守住）

| 编号 | 不变量 | 违反后果 |
|---|---|---|
| INV-01 | 空值 ≠ 0。未测量/未填写保持 null，不得写 0 | 统计被污染，家长误判 |
| INV-02 | PB 仅统计「有效 + 池长已知 + 同距离/泳姿/池长」 | 虚假进步 |
| INV-03 | 成绩以整数毫秒为准，显示值不得反解回写 | 精度丢失 |
| INV-04 | 未完成/已取消的训练不计入任何实际量统计 | 训练量虚高 |
| INV-05 | 实际次数缺失时不按计划次数补齐；已知部分与完整总量分开显示 | 造假 |
| INV-06 | 技能等级只能人工确认，打卡次数不得换算等级 | 伪精确 |
| INV-07 | 目标达成必须有确认人 + 说明 + ≥1 条有效证据 | 虚假达成 |
| INV-08 | 公开摘要只能包含白名单字段；多一个字段即构建失败 | 隐私泄漏 |
| INV-09 | 服务端拥有 `athleteId`/`version`/`createdBy`/`updatedAt`，客户端传入一律忽略 | 越权与伪造 |
| INV-10 | 一切删除是逻辑删除，历史保留且版本单调递增 | 不可恢复 |
| INV-11 | 教练越权操作在接口层拒绝，不依赖前端隐藏按钮 | 安全漏洞 |
| INV-12 | 样本 < 2 条不计算改善率、不画趋势 | 误导 |

### 5.5 并发与版本

- 读：返回 `X-Nico-Revision` 响应头，前端记住。
- 写：必须带 `If-Match: <revision>`；不匹配返回 `409` + 当前版本摘要。
- 新建：带 `clientRequestId`（UUID），服务端存请求哈希；同哈希重试返回原记录，不同内容返回 `409`。
- 冲突处理：不静默合并、不静默覆盖；用户必须在「查看最新」与「覆盖」之间显式选择。
- 快照：版本化 JSON 业务状态 + 台账表；台账只追加，不 UPDATE 业务事实。

### 5.6 迁移策略（从单儿童到多儿童）

1. **不动现有数据**：为既有记录批量补 `athleteId = 'nico-migrated'`，创建对应 Athlete 记录。
2. 新增 `athletes` / `coachGrants` 集合，扩展台账白名单（只放宽，不缩窄）。
3. 服务端在读路径兼容「无 athleteId」的旧记录，归入默认运动员。
4. 前端所有查询加 `athleteId` 过滤，默认选中第一个运动员。
5. 迁移前自动备份；迁移可重复执行且幂等；回滚保留新集合与宽约束，用向前修复而非删数据。
6. 全量回归：现有 62 个测试文件必须全绿，新增多儿童隔离测试。

## 附录 B：文案语气规范

- 用「已记录 / 未记录 / 未测量 / 未知」，不用「无数据」这种含糊说法。
- 用「参考区间」「观察结论」「依据」，不用「建议值」「应该达到」。
- 不用「战力」「天赋」「潜力」「突破」「保证」「一定能」。
- 鼓励指向过程：「这周比上周多游了 400 米」，而不是「进步很大」。
- 报错必须说明「发生了什么 + 数据现在在哪 + 下一步怎么做」，不能只说「操作失败」。
