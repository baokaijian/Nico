# 分期实施与回滚计划

## P0 / V1.0

1. 审计与需求：七份 docs，记录基线与证据。
2. 访问范围：`App.jsx`、本机/云端鉴权、公开构建、访客检查、接口测试。访客只请求公开摘要和白名单媒体；完整快照/集合/原片登录读取；初始改密会话先设置。云端构建不嵌入静态业务副本，避免撤回后回退旧摘要。独立静态发布保留兼容模式。
3. 历史安全：共享计划历史合并，修改两个 restore；版本单调递增，不将计划改动当作已训练。使用临时库测试旧备份恢复、新版本、冲突及回滚。
4. 成绩标准：精确毫秒、兼容迁移、有效性、计时标签；PB/趋势/报告统一口径。保留用户确认的 `00:56:17`。
5. 训练闭环：实际训练组、模板、复制上次、完成状态、媒体关系。空值与零完成区分，不用计划量补实际。
6. 基础模型/安全：TypeScript、归属与时间戳、请求幂等、操作审计、长期导出。

每项最小变更先在本机与隔离测试验证，再发布同版本前后端。已授权的可逆代码变更直接推进，不改变原始输入、密码或公开选择。涉及高风险拆表、物理删除或不兼容替换时先给方案。

## V1.0 第二阶段：成绩标准化

受影响文件：新增 TypeScript 成绩领域模块及类型检查；增强 prd/domain、公开白名单、成绩录入、概览/报告/打卡统计、迁移工具与对应测试。整数 timeMs 为唯一精确值，旧 time/seconds 继续作为兼容展示，保存原始输入，百分秒显示不回写损失毫秒。不同项目与池长隔离，只有人工确认“有效”且池长已知的记录参与 PB 和改善率；缺少有效性标为“未核验”，不能自动确认。失格/无效仍保留。

迁移先在真实快照副本、已删成绩及旧备份上检查，保留备份、公开选择、关联和所有非成绩数据。重复执行无变化，冲突禁止覆盖；原始输入不可改写。对已有业务状态仅新增字段，不删除旧字段，不拆表。回滚保留整数值及原始输入，用向前修复避免再次按展示值计算。所有新逻辑使用可由 Node/Vite/Deno 直接运行的可擦除 TypeScript；原有 JSX/MJS 逐步接入，不同时重写框架。

## P1 / V1.1

新增技能标准/评估、五状态目标、证据人工确认和计划复盘。复用现有打卡/计划，不用薄弱点练习冒充能力测评。每个实体补充服务端校验、导出、删除恢复和迁移测试。

## P2 / V1.2–V2.0

人工里程碑、媒体标签和对比、可编辑月年报告、训练分析中心；之后再增加有明确来源的 AI 草稿和可选协作。保留空状态与计算说明。

## 发布与回滚

每阶段更新 changelog：影响文件、迁移、测试、移动端结果、剩余需求。运行 lint/typecheck/test/build/公开产物检查；Pages 与 Edge Function 分别确认部署版本与状态。以无会话请求验证公开入口正常、完整档案 401、写入 401、未授权媒体不可读；登录验证 CRUD、CSRF/CAS、恢复和导出。发布后读取数据版本确认没有意外写入。

第一阶段发布前先执行 data-model 所列台账兼容补丁，核对原有数据摘要不变，再部署 API 和 Pages。现有函数工作流只发布函数，不自动执行数据库迁移。GitHub secret 按[官方条件用法](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets)放在 job 环境变量并控制步骤；自定义账号入口继续在[函数内鉴权](https://supabase.com/docs/guides/functions/auth)，不把公开摘要置于管理员登录之后。

回滚优先向前修复或撤销代码提交并重新发布；**不恢复允许匿名完整读取的旧版本**。数据兼容字段先保留，迁移前备份和新写入单独保全，禁止为回滚覆盖真实后续记录。新阶段可独立运行，不以全部 V2 完成为单次上线前提。
