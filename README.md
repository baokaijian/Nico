# Nico 游泳成长记录

围绕计划、实际记录、录像复盘和周期报告管理单个儿童的游泳成长。分析是可追溯的规则汇总，训练建议是待家长依据教练反馈确认的草稿；没有随机生成的成绩、体能、恢复评分、天赋分或达级预测。

内容与训练方案默认可直接查看，不需要登录；登录只作为信息录入入口。管理员账号用于录入、修改、导出与恢复记录，未登录时页面只读。网站仍由GitHub Pages提供，账号、记录与素材由Supabase承接。详见[管理员登录说明](ADMIN_LOGIN.md)。

## 数据与运行方式

- `data/original-input.json` 是原始录入档案。首次启动完整导入 SQLite，之后不改写该文件（本次迁移前为server/db.json，原字节保留）；旧成绩、身体测量、目标和素材原字段保留。
- 接入Supabase的页面以云端Nico事实库为当前数据来源。本机`data/nico.sqlite`保留迁移前档案；独立本机模式仍使用此库。每次修改前将旧版本备份到 `data/backups`，目录不参与版本管理。
- `data/uploads` 是唯一原片来源。兼容播放副本和封面在同目录生成，原片不改写。删除记录是移入回收站，不删除原片。
- 页面通过接口读取实际记录；连接失败不伪装成空数据或保存成功。浏览器仅暂存未提交表单，不充当第二份事实库，不自动合并旧版本的 `nico_*` 缓存。
- 成绩按距离、泳姿、池长区分；出发、计时、测试任务、赛事条件未知时明确标注未知。性别和生日不猜测。
- 计划草稿由服务端规则引擎（`shared/plan-engine.mjs`）依据已录入记录计算，写入保留槽位 `plan-draft`，与人工计划并存。引擎只输出"参考区间 + 观察结论 + 依据"：训练量需近4周≥6条训练记录且分布于≥3周，强度需近2周≥2条恢复记录或近4周≥3条含RPE训练，未达门槛的整段维度置空态并说明门槛，不填充任何默认值或历史外推。草稿被人工编辑后不再自动覆盖。

## 本机启动

需要 Node.js 24 或更高版本，以及 FFmpeg / FFprobe（处理素材时使用）。本次验证使用 Node.js 26.10.0；使用 Node 内置 SQLite，无新增数据库服务。

```sh
npm ci
# 当前工作目录已保留你的原始输入，无需初始化。
# 新安装才使用 npm run init:data -- /你的原始档案.json
# 仅明确创建全新空档案时使用 npm run init:data -- --empty
npm run dev
```

访问 `http://127.0.0.1:5173/Nico/`。前端与服务端默认只监听本机，前端通过代理访问 `/api`。

已有素材的兼容副本：

```sh
npm run media:prepare
```

生成最高720p、30fps、H.264/AAC的播放版本与封面；原片用于需要更高细节的复盘。上传后异步处理，在复盘页刷新状态。格式不符或处理工具不可用时返回明确错误/保留原片，不能将失败称为已处理。

公网管理员上传视频时，先保存原片，再由当前设备生成H.264/AAC播放副本与JPEG封面并保存到Supabase私有存储。处理期间保持页面打开；离开、取消或失败后，原片仍在，可从影像列表重试，无需再次上传。工具仅在处理视频时加载，普通访客看成绩/视频不会下载约32MB处理核心。大小限50MB，慢设备可改在电脑处理；设备处理整体超时12分钟，不冒充后台持续处理。副本需校验原片SHA-256、MP4轨道/尺寸/时长和JPEG格式；并发更新冲突时保留原记录，副本与封面全部保存成功后才显示已处理。新增视频不会自动进入展示摘要，仍须在摘要范围中勾选。

浏览器处理依赖固定版本 `@ffmpeg/ffmpeg 0.12.15`、`@ffmpeg/core 0.12.10`，核心在独立Web Worker中运行，随站点提供组件许可和对应源码链接。维护时注意该核心的[ffprobe返回值问题](https://github.com/ffmpegwasm/ffmpeg.wasm/issues/817)：探测必须验证新生成JSON文件及轨道/时长，不仅检查返回值。

## 界面结构

页面采用传统网页布局：顶部状态栏（Logo、主导航、记录查找、登录入口/用户信息）+ 上下文条（当前位置、记录类型子导航、主操作）+ 内容区（左侧分区导航 + 主内容）。未登录同样展示全部记录、AI训练方案与数据分析报告，只是不能录入或修改；页面不额外标注授权来源。登录不设独立页面：状态栏右端的「登录」按钮就地展开弹层（含首次设置密码表单），已登录后变为用户胶囊（修改密码 / 退出登录）；会话失效时在同一位置重开弹层，页面与滚动位置不变。窄屏下分区导航收为抽屉、登录改为底部弹层。视觉为纸白底 + 墨色文字 + 泳道蓝主色，层级靠结构与留白区分，数值一律等宽对齐；不使用外部字体或图库。

## 使用流程

1. **今日**：已录入PB、数据覆盖、当前重点及带来源的分析。缺少测量显示未评估。
2. **本周**：展示当前日期适用的确认计划（周期重叠时在页面内单选采用哪一份），本周已确认课次的执行覆盖率，以及每次录入证据集合后由服务端在同一事务内自动重算的计划草稿——含周期划分、阶段目标、训练量参考区间、强度与恢复观察、命中规则与门槛、依据的数据范围。草稿不含任何具体组表；组数、距离、休息仍由家长依据教练反馈手动录入。“以此草稿创建计划”只预填名称/周期/重点，不预填未经录入的数值。四周建议流程与草稿相互独立标注。
3. **打卡**：家长依据教练反馈、已审核录像观察或同项目成绩对比确认薄弱点（平台只给候选，不自动写入），练习后逐次打卡；页面展示本周次数 / 周目标、连续天数、28天打卡分布、薄弱点来源与依据原文、能力成长（首条→已录入最好成绩，仅同项目比较）。每次打卡只记录已发生的练习，未打卡不代表没有练习。
4. **记录**：简版课后/恢复/成绩/测量优先，其余字段折叠为补充详细字段；支持按日期范围、泳姿、距离、池长、记录性质筛选；空列表区分“未录入”与“无匹配筛选结果”。成绩、体能、身体数据只填实测。0与留空不同。
5. **复盘**：完整八章报告、独立HTML下载、浏览器打印为PDF；第3章引用自动生成的计划草稿并记录引擎标识、依据指纹、数据范围与命中规则；第8章汇总薄弱点打卡与能力成长；录像批注明确运动员/泳道、起止时间、证据限制、关联记录和审核状态。
6. **档案**：确认基础档案，保留个人目标原文，查看官方标准，可选生成展示摘要，导出/恢复完整备份及回收站恢复（需登录）。

原始目标中的未核实规则、旧标准和确定性承诺只作为历史录入原文，不作为已确认训练指令。女子50米自由泳现行参考：长池二级31.50秒/三级36.00秒，短池二级30.50秒/三级34.00秒；其他泳姿已复核的50米二级线统一配置。其他项目和男子标准未内置时直接查官方完整表，不猜测。达参考线、满足授级赛事条件与获得证书分别判断。

官方来源：https://www.sport.gov.cn/rlzx/n5633/c28294142/part/28294152.pdf

## 可靠保存与冲突

- 所有修改需带最新读取版本，服务端事务写入；其他设备先修改时返回409，输入保留。
- 记录和计划编辑保留其开始编辑的版本。遇到冲突，先刷新查看最新记录，再明确采用已核对的新版本重试。
- 网络中断可能发生在写入前或确认响应丢失之后。因此先刷新核对是否已有该记录，再重试；页面不会声称未收到响应就一定没写入。
- 错误响应不清空表单、不从列表删除记录。草稿仅在此设备，可单独导出。
- 完整备份包含私有记录。恢复前自动备份现有版本；素材原文件需连同 `data/uploads` 保管，JSON备份不包含视频字节。
- 停服务后整体复制 `data` 可保留全部数据/素材。只复制正在写入的 SQLite 主文件不完整，需连同WAL文件或先停服务。

## 公开摘要与 GitHub Pages

访客无需登录，只能查看所选成绩与影像。展示页分三个入口：**概览**（发布日期、统计、各项目最好成绩与迷你趋势、最新影像预览）、**成绩**（按"距离·泳姿·池长"筛选的时间线，差距只与同一项目的已公开成绩比较，不跨项目换算、不预测）、**影像**（卡片网格与播放弹窗）。未选择公开内容时整页只显示说明，不填充示例数据；成绩为原始录入值。展示页与管理页共用同一套设计 token（纸白 + 泳道蓝，浅色单一主题，支持减少动效），不使用任何外部字体或图库。管理员登录后可以维护云端数据；完整档案仅通过认证接口读取，不包含在Pages产物里。以下独立公开包流程仍适用于静态快照；云端模式的白名单修改通过接口生效。

1. 在档案页勾选允许公开的成绩/素材，核对其他儿童素材范围，填写确认人和日期，保存白名单。
2. 点击“生成本地公开发布包”，得到 `release/public-summary.json` 与所选播放文件。此动作只生成本地文件，不上传网站。
3. 检查发布包，执行 `VITE_APP_MODE=public npm run build` 和 `npm run verify:public`；构建只读取 `release`，不读取私有事实库或原始档案。公网构建输出 `dist`，私有维护构建输出 `dist-private`，不能互相替代。
4. 将已确认的发布包及代码提交到现有源仓库后，GitHub Actions使用唯一Pages artifact流程发布。仓库Pages设置应选择GitHub Actions；PR只检查，合入master后才发布。PR检查与正式发布使用不同并发组。

没有确认公开内容时，默认发布包为空。这是发布范围未选择，不表示私有记录被删除。`public/uploads`、`docs`、根`assets`不再作为发布来源；旧生成文件已移至忽略的 `legacy-archive`，一致素材副本清理记录见 `review/RESOURCE_MIGRATION.json`。旧目录可从原片和该清单恢复。

现网继续开放。自动部署与正式容器构建检查发布包是否已确认且非空；未选择展示内容时停止部署，不用空页面覆盖现网。该检查不阻止本机预览空的展示包。不要将开发预览、私有数据库、上传目录或本机维护接口代理到公开域名。

如不用Pages，可在完成公开构建后执行 `npm run serve:public`，预览 `http://127.0.0.1:8080/Nico/`。该独立进程只提供展示包，不打开数据库，不读取维护密钥，不安装写入或上传路由；所有非GET/HEAD请求返回405，私有API返回404。部署到自己的服务器时设置 `NICO_PUBLIC_HOST=0.0.0.0`，由HTTPS入口代理到该进程。

默认Dockerfile也是公开只读服务：运行阶段只复制公开构建、只读入口与校验模块，不复制私有维护后端或data。运行时不挂载私有数据，可使用只读容器文件系统。当前环境没有Docker运行程序，容器构建与真实HTTPS部署尚未验收。

原始录入文件与原片仍包含家庭资料；家庭原始档案、素材、review报告已移到忽略目录，不再进入后续代码提交；源仓库历史中的旧数据需要单独处理。公开容器只打包代码与确认过的展示包，不挂载私有data目录；完整备份按私有资料管理。Pages发布产物与源仓库是不同范围。

## 本机维护与私有服务

当前公网同时支持匿名查看与经过认证的管理员管理，由Supabase后台承接：读取（记录、AI训练方案、数据分析报告、素材）默认开放，写入、导出备份、恢复与发布仍需管理员会话。若部署环境需要连读取也受控，设置 `NICO_REQUIRE_LOGIN_FOR_READ=1` 即可恢复“读取也需登录”。独立本机维护服务默认只监听回环地址；以下密钥角色配置仅用于现有维护API的兼容调用。

- 私有维护服务误设 `NICO_HOST=0.0.0.0` 或其他非回环地址时，强制身份验证和只读；即使管理者密钥有效也不能写入。缺少管理者密钥则拒绝启动。本机也可使用 `NICO_READ_ONLY=true` 禁止修改。
- 配置 `NICO_OWNER_TOKEN`、可选 `NICO_COACH_TOKEN`、`NICO_VIEWER_TOKEN`，每个至少32字符，分别用于家长管理、协助录入（同一家庭的第二位录入者）、授权只读访问。平台不由教练本人操作：教练的反馈由家长照录。不要写进源码、Vite变量或公开包。
- `NICO_ALLOWED_ORIGINS` 用逗号分隔允许的实际页面来源；不要用通配符。一个服务只提供Nico这一份档案，凭据权限限于该档案。
- 本机维护中的协助录入角色可维护成绩、水上训练、计划、批注、薄弱点与打卡；身体、恢复、发布和备份操作限家长管理者。非回环监听时所有角色均不可写入。现有私有读取接口仍面向同一个完整档案，不能作为远程角色隔离服务上线。
- 私有前端构建使用 `VITE_APP_MODE=private npm run build`；API同源时不用设置地址，否则配置 `VITE_API_URL`。用 `NICO_WEB_DIR` 指向该构建目录，服务可在 `/Nico/` 提供登录页面。
- `.env.example` 提供字段说明。Node不自动读取`.env`，由部署环境注入变量，或使用 `node --env-file=.env server/server.js`。
- 默认Dockerfile提供公网只读构建，不提供私有数据维护接口。管理员远程服务使用Supabase Edge Function；Docker仅用于独立静态展示预览。

## 游客只读访问（未登录浏览）

未登录访客可直接浏览记录、AI 训练优化方案与数据分析报告；登录只用于录入与修改。规则由四处共同决定，改动任一处都要重新核对：

| 位置 | 文件 | 只读（GET/HEAD） | 写入与身份功能 |
| --- | --- | --- | --- |
| 后端鉴权中间件 | `server/server.js` | `/api/snapshot`、`/api/<集合>`、`/api/media/:id/content/:variant` 匿名放行，角色置 `viewer` | POST/PUT/DELETE、`/api/backup`、`/api/restore`、`/api/public-export`、`/api/public-preview`、`/api/publishing`、`/api/profile` 仍需会话 |
| 云端适配层 | `server/cloud-api.mjs` | 同上，`openRead` 白名单；`/api/auth/session`、`/api/public-summary`、`/api/public-media` 始终开放 | 同上，`requireLoginForRead` 为 true 时读取也要登录 |
| 前端登录态判断 | `src/App.jsx`、`src/services/api.js` | `fullView` 只看是否有后端，不看登录态；未登录同样渲染今日/本周/打卡/记录/复盘/档案 | `readOnly` 跟随登录态，隐藏录入、修改、删除、上传、备份恢复、改密码等入口 |
| 组件写控件 | `Records`/`PlanViewer`/`Practice`/`Profile`/`MediaGallery` | 列表与详情只读展示 | `readOnly` 或 `role !== 'owner'` 时表单不渲染 |

本机与云端都保留一个开关：设置 `NICO_REQUIRE_LOGIN_FOR_READ=1`（本机环境变量 / Supabase 项目 secret）即可恢复“读取也需登录”。默认不设置，即开放只读。前端遇到匿名 401 时只提示“此服务当前要求登录”，不会强制弹出登录层；只有携带凭据的请求失效才提示重新登录。

验证未登录浏览（不带 cookie、不带 Authorization）：

```sh
npm run server                                   # 或已部署的云端地址
npm run verify:guest                             # 默认 http://127.0.0.1:3001
npm run verify:guest -- https://oeyirzlgqixvcxofimit.supabase.co/functions/v1/nico-api
```

脚本只读检查 22 项：会话查询 200 且未登录、快照 200 且 `role=viewer`、各集合列表 200、素材内容不返回 401；写入、导出备份与发布预览必须 401。浏览器验证：用无痕窗口打开站点，能直接翻看各页；尝试提交任意记录会提示登录，接口返回 401。

云端函数需要单独部署才会生效，GitHub Pages 工作流不会部署它。配置仓库 secret `SUPABASE_ACCESS_TOKEN` 后，`.github/workflows/deploy-function.yml` 在 `server/`、`shared/`、`supabase/functions/` 变更时自动部署并跑上述游客校验；也可手动执行：

```sh
supabase functions deploy nico-api --project-ref oeyirzlgqixvcxofimit
```

部署后确认线上没有遗留 `NICO_REQUIRE_LOGIN_FOR_READ=1`（`supabase secrets list`），否则线上仍会拒绝游客读取。

## 验证

```sh
npm run check
```

包含静态检查、基于原始输入的分析/报告检查、临时环境API验证、生产构建与公开白名单检查。接口测试使用明确标识的临时记录与确定性非法请求，不写入真实档案、不生成随机实测数据。真实家长录入用时、与教练核对反馈和远程服务运维是上线后的实际流程，不由自动测试冒充。

评审、任务清单与本次验收记录位于 `review`。
